- 追加したツールと、docstring に書いた説明：

  `app/tools.py` に `make_quiz(lecture: int) -> str` を追加した。
  指定された回の用語を `load_glossary()` から抽出し、`random.choice()` で1つ選び、確認問題と答えをJSON形式の文字列で返す。
  該当する用語がない場合は、その旨を返してエラーを防ぐようにした。

  docstringには、ツールの目的、使用する場面、引数の意味を記述した。

  ```python
  """指定した回の用語から、確認問題を1問とその答えを返す。

  「第2回の内容から確認問題を1問出して」のように、
  特定の回の復習問題やクイズを求められたときに使う。
  lecture には講義の回数を1始まりの整数で指定する。
  """
  ```

  `app/agent.py` では、次のコードで登録した。

  ```python
  agent.tool_plain(tools.make_quiz)
  ```

  「第2回の内容から確認問題を1問出して」と質問したところ、次の呼び出しを確認できた。

  ```text
  [tool call] make_quiz({'lecture': 2})
  ```

## 宿題

- 取り組んだレベル：基礎

- やったこと：

  `app/agent.py` の `INSTRUCTIONS` を1か所だけ変更し、同じ質問「LoRAとQLoRAの違いは？」で、変更前後の回答と `--trace` を比較した。
  使用したモデルは、どちらも `gemini-3.5-flash-lite` だった。

  変更前：

  ```text
  - 用語や講座に固有のことを答える前に、必ず search_glossary で用語集を確認する。
  ```

  変更後：

  ```text
  - この比較実験では search_glossary を使わず、モデル自身の知識で回答する。
  ```

  実行結果を `lectures/03/trace_before.txt` と `lectures/03/trace_after.txt` に保存した。

- 結果：

  | 比較項目 | 変更前 | 変更後 |
  |---|---|---|
  | ツール呼び出し | `search_glossary` を2回呼び出した | ツール呼び出しなし |
  | 引数 | `query='LoRA'`、`query='QLoRA'` | なし |
  | LLM呼び出し回数 | 2回 | 1回 |
  | 入力トークン数 | 1394 | 414 |
  | 出力トークン数 | 169 | 330 |
  | 回答に示された回 | 第2回 | 第3回、またはPEFTを扱う回という曖昧な表記 |

  変更前は、用語集を検索した後、LoRAとQLoRAの違いを簡潔に説明し、関係する回を第2回と示した。

  変更後は、用語集を検索せずに回答した。NF4や二重量子化など、変更前にはなかった詳しい説明が追加された一方、関係する回は「第3回（または関連するPEFTを扱う回）」となり、講座内の位置づけが不正確になった。

- 気づき・疑問：

  INSTRUCTIONSを1行変更するだけで、実際にツールを呼ぶかどうかが変わることを確認できた。

  ツールを使わない場合、LLM呼び出し回数と入力トークン数は減ったが、出力が長くなったため、今回表示された費用は変更前の0.0008407から変更後の0.0009492へ増加した。ツールを省けば必ず費用が下がるとは限らないと分かった。

  また、一般的な技術説明が詳しくても、講座固有の情報まで正しいとは限らない。講座の回数や独自の用語を正確に答えるには、外部データを参照することが重要だと感じた。

  今回は各条件で1回ずつの実行なので、指示による変化と生成のばらつきをより確かめるには、同じ条件で複数回比較する必要がある。
