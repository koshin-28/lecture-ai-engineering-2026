## 宿題

- 取り組んだレベル：基礎
- 変えた設定やデータ：
  - `num_train_epochs` のみを20から10に変更した。FAQと評価データは変更していない。
  - 2つのファイルを比較し、CONFIGの他の値とライブラリのバージョンが同一であることを確認した。両方とも自分で学習を実行した。
  - 20 epochsは `result (2).json`、10 epochsは `result (1).json` を使用した。lossと学習時間は、各ファイルの末尾に追記した学習ログの値を使用した。
- 結果（比較表や数字）：

  | 指標 | 元の設定：20 epochs | 変更後：10 epochs |
  | --- | --- | --- |
  | 学習前 format_rate | 9.52%（2/21） | 9.52%（2/21） |
  | 学習後 format_rate | 100%（21/21） | 100%（21/21） |
  | 学習前 content_rate | 0%（0/21） | 0%（0/21） |
  | 学習後 content_rate | 90.48%（19/21） | 80.95%（17/21） |
  | 最終記録のTraining Loss | 0.014217 | 0.097288 |
  | 学習時間 | 242.2217秒 | 121.8775秒 |
  | 退行した質問 | なし | なし |

  エポック数を半分にすると、学習時間は約49.7%短くなった。10 epochsでも形式遵守率は100%に達した一方、内容正解率は20 epochsより9.52ポイント低く、正解数は2問少なかった。最終記録のlossも10 epochsの方が高かった。今回の実験では、学習時間の短縮と内容正解率の間にトレードオフが見られた。

  セクション6の4問の分類は、両設定で同じだった。どちらも教員名と次回のテーマには確認を求めたが、FAQにない最終課題の締切には断定した。20 epochsに増やしても、この誤った断定は解消しなかった。

  なお、各設定1回の実験であるため、常に20 epochsの方が良いとは断定できない。また、最終記録のTraining Lossは学習データに対するログ値であり、未知の質問への正解率そのものではない。

- ファインチューニングが向く場面・向かない場面についての考察：
  - 向く場面：決まったJSON形式や回答の書き方を安定して守らせたい場合。今回、10 epochsでも形式遵守率が9.52%から100%に改善したため、一定の形式や応答パターンを学ばせる用途に有効だと考えた。
  - 向かない場面：最新情報の正確性や、資料に根拠がない質問への適切な判断を、ファインチューニングだけで保証したい場合。今回も最終課題の締切への誤った断定が残ったため、資料の検索や根拠の確認、人による確認を組み合わせる必要があると考える。
  - 学習量はlossや形式遵守率だけで決めず、内容正解率、根拠のない断定の有無、学習時間も合わせて判断したい。
